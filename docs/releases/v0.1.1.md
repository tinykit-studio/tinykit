# Tinykit v0.1.1 — maintenance update

A small update focused on getting Tinykit running smoothly again and making it easier to use your preferred model provider.

- Repair Docker installation and startup, use Node.js 22, and keep local credentials and databases out of image builds.
- Add DeepSeek and custom OpenAI-compatible providers, including keyless local servers, exact model IDs, and configurable API URLs.
- Finish domain connection for existing and new apps while keeping the dashboard accessible.
- Fix Canvas image uploads, saved-image updates, failed-upload recovery, and rapid-save ordering.
- Bundle the matching Svelte runtime for more reliable previews and publishing; retry temporary failures loading other CDN dependencies.
- Improve realtime updates, editor type correctness, and deployment documentation. Docker and Railway now default to a 10 MB request-body limit.

Thanks to the community report and Docker fix in [#8](https://github.com/tinykit-studio/tinykit/pull/8).

## Upgrading

Back up your PocketBase data, rebuild, and restart Tinykit. Docker users should retain the same Compose project name and data volumes; see the [Docker update instructions](../../deploy/docker/README.md#existing-installations-and-updates).

Republish existing apps to receive the generated runtime and data-client fixes. The updated Canvas template applies to newly created Canvas apps. Existing app source and records are not replaced by the upgrade.

AI is optional. Templates, manual editing, and running apps do not require an LLM key. See [provider configuration](../ai-providers.md) for custom endpoints and Docker networking. The connection test checks connectivity and authentication; your chosen model must also support tool calling for the builder.

The local-agent companion and unfinished JSON data importer are deferred from this release.

The version follows the package's previous `0.1.0`; the first GitHub release was tagged `v0.0.1`.
